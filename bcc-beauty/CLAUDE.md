## ビルドの仕組み（重要）

サイトは**静的HTMLジェネレータ**で生成する。`bcc-beauty/*.html` は**生成物**。手で直接編集しない。

- **ソース・オブ・トゥルース**:
  - `_build/gen.mjs` … ジェネレータ本体（プレーンなES modules・Node）。全ページのデータ・
    デザイン(CSS)・レイアウトがここに入っている。
  - `_build/writeups.json` … 各サービスの「資料の内容」本文（dossier）。`{sid, overview, sections:[{heading, bullets[]|text}]}` の配列。
- **再生成コマンド（検証済み・再現可能）**:
  ```sh
  cd bcc-beauty/_build && node gen.mjs ..
  ```
  → `bcc-beauty/` 直下に `index.html` / `404.html` / 各サービス `<id>.html`（計25詳細＋index＋404）を出力。
  （cwd=_build なので `writeups.json` を読み、出力先 `..` = `bcc-beauty/`）
- **手順**: `gen.mjs`（または `writeups.json`）を編集 → 上記コマンドで再生成 →
  `git add bcc-beauty/` → コミット → push で Vercel 自動デプロイ。
- 画像は `notion/<id>/logo.*`・`notion/layer-design-works/case-*.jpg` に自己ホスト（gen.mjsは画像処理しない）。

## gen.mjs のデータモデル

| 変数 | 役割 |
|---|---|
| `services[]` | `{id, cat, name, desc}`。カード＆詳細ページの基本。 |
| `categories[]` / `enOf{}` | カテゴリ順とその英語ラベル（タブに表示）。 |
| `RICH{}` | サービス別の詳細情報（下表）。キー=service id。 |
| `DOSSIER`（=`writeups.json`） | 「資料の内容」。`overview` + `sections`。アコーディオン表示。 |
| `DOC{}` / `DOC_RICH` | Notion公開ページの「資料（詳細）を見る」リンク。`DOC_RICH` に入れたidだけ表示。 |
| `LOGO{}` / `DARKLOGO` | カード＆詳細のロゴ画像。`DARKLOGO` は濃色タイルに載せる。 |

### `RICH` のフィールド（サービス別）
- `intro` … 見出し下のリード文（常に表示）。
- `features[]` … 特長リスト（**curatedページ=`cases`ありのみ表示**。dossierがある通常ページでは非表示＝dossier側で説明）。
- `lineUrl` … そのサービス**専用**の公式LINE。あると「〈ブランド名〉専用の公式LINEへ」ボタンを出す。
- `panelTitle` … CTAパネルの見出し（既定「ご相談・ご予約」）。
- `links[]` … CTAを自前で組む場合。`{label, href, primary?(濃色ボタン), note?(小さい注記)}`。指定するとlineUrl/docより優先。
- `gate` … パスワードゲート（クリックでPW表示→サイトを開く）。`{pw, href, revealLabel, openLabel}`。drive-blueで使用。
- `review` … 「お客様の声」引用（1文字列）。
- `cases[]` … 施工写真つき実例（layer-design-worksのみ。curated扱い）。
- `logo` … ロゴパス（LOGO未登録でも個別指定可）。

### dossier（`writeups.json`）の見出し自動整形
- 見出しに `流れ/STEP/ステップ/フロー` → 連番タイムライン（`<ol class="steps">`）
- 見出しに `料金/プラン/費用/価格/目安` → カード表示（bullet を `：` で名前:内容に分割）
- それ以外 → 特長リスト（`<ul class="feature-list">`）

### CTA（ご相談・ご予約パネル）のロジック
1. `r.gate` があればパスワードゲートwidgetを出す。
2. `r.links` があればそれをボタン化（`primary`=濃色、最初のnoteを小注記に）。
3. なければ: `lineUrl`→公式LINEボタン、`DOC_RICH`なら「資料（詳細）を見る」、
   LINEありでdocなしなら「ほかのサービスを見る」。
4. **公式LINEも links も doc も無ければパネルごと非表示**（＝連絡先が無いサービスは連絡ボタンを出さない）。
   ※以前あった「オープンチャットで相談」フォールバックは廃止済み。

## 決まっていること / DO・DON'T（恒久）

- **カタログ段階で料金・「無料」を書かない**（実料金は各サービスの公式LINE側で案内されるため）。
  - ⚠️ **例外: `/tonari-seminar`（隣店セミナー講師紹介）だけは実額を載せる**（オーナー確定 2026-08-11）。
    理由は**講師を選ぶのに金額の比較が要る**ため。**ルール違反ではないので、料金を消しに行かない。**
- **公式LINEボタンはサービス名入り**（例「ヘアキャンプスクール専用の公式LINEへ」）。BCCの公式LINEと混同させない。
- **連絡先が無いサービスは連絡ボタンを出さない**（パネルごと非表示）。
- **外部URLの追跡パラメータ（`fbclid` 等）は除去**してから使う。
- **和文はゴシックのみ**。原色・絵文字・CSS装飾過多はしない。
- **`main` に直接 push しない**。作業ブランチ → draft PR → ready → squash merge。main マージ→Vercel自動デプロイ。
- **生成HTMLを手編集しない**。`_build/gen.mjs`（＋`writeups.json`）を直して再生成。
- **`/stylemanager` は転送であり、BCC 内に実体を持たない**（オーナー確定 2026-08-27）。`vercel.json` の
  `redirects` で **新LP <https://stylemanager-lp.vercel.app> へ 302 転送**するだけ。HTML は置かない。
  - 🚫 **スナップショットを置き直さない**（＝再ミラー案は不採用。**再提起しない**）。理由: 2026-07-24 に
    スナップショットで作ったところ、元が更新されてもミラーが追随せず、**旧値のまま公開され続ける事故が実際に起きた**
    （フォロワー数の誤り・非公開方針の実名が残存）。さらに元ページ自体が空になり「元から再取得」も不能になった。
    **ズレる構造そのものを消す**のが今回の決定。
  - 🔴 **このURLは 2026-08-11 に会員へ LINE 一斉配信済み**。会員の手元にリンクが残っているため、
    **`/stylemanager` を消さない・404 にしない**。転送先を差し替えて生かし続ける。
  - 302（`permanent: false`）にしてある。新LP側が独自ドメイン化などで **URL を変えたら転送先だけ直す**
    （301 だとブラウザにキャッシュされ、変更しても旧転送先に着く人が出る）。内容の正は StyleManager 担当。
  - ⚠️ **疎通チェックで「全ページ 200」を条件にしない**。`/stylemanager` は**正常時が 307**（転送）なので、
    200 固定で判定すると**成功しているのに失敗と報告し続ける**（2026-08-27 に StyleManager 側の監視タスクが
    実際にこれを踏みかけた）。**リダイレクトを追った先（`curl -L` の着地）で判定する**こと。
  - 🔴 **BCC は転送先に依存している**。`stylemanager-lp.vercel.app` が**落ちる／URLが変わると、
    会員に配信済みのリンクが死ぬ**。**転送先が変わるときは `vercel.json` の `redirects` も同じ回に直す。**
    ⚠️ これは 2026-08-27 に StyleManager 側が踏んだ「元が変わってもミラーが追随しない」と
    **向きが逆なだけの同じ穴**（実体を持てば追随漏れ、転送にすれば転送先の消失）。どちらの形でも
    **2つの資産が別々に動く限り、片方を変えたら他方も同じ回に直す**必要がある。
  - 📌 **どう気づくか**: 転送先を変えるときは **StyleManager 担当が「着手前」に連絡する取り決め**
    （2026-08-27 に相互合意。事後だと会員の配信済みリンクが死ぬため）。先方の CLAUDE.md にも
    「URL変更時は BCC担当へ連絡」と明記されている。
    ⚠️ **ただし連絡に依存しきらない**。LP 側の障害・失効など**連絡が来ない壊れ方もある**ので、
    `/stylemanager` を `curl -L` で着地まで追う確認は、こちらでも折に触れて行う。
- **秘密情報をコミットしない**。自分のモデル識別子はコミット/PR/成果物に書かない（チャット内のみ）。
- push前チェック: 生成物（`bcc-beauty/`）にAPIキー/アクセストークン/モデル識別子らしき
  文字列が混入していないか grep で確認してから push する（何も出なければOK）。
- **`/drive-blue` のパスワードゲートは「意図的なクライアント側の軽い目隠し」で、秘匿性は求めていない**
  （オーナー確定 2026-07-28）。公開HTMLに平文で入っているのは**既知かつ許容**。発注用の社内向けページのため、
  **サーバー側認証への作り替えは不要**。⚠️ セキュリティ欠陥として再提起しない（同じ確認が何度もオーナーに飛ぶ）。
  📌 **影響範囲の注意**: このパスワードは **オンラインサロン（ile-academy.online）の会員PWと同一運用**である
  ことが判明している（2026-08-11 受付経由。実検証はオンサロ担当が本番 `/__auth` で実施・2026-08-10）。
  **BCC 側だけの都合で値を変えると、別事業（ing側）の会員が締め出される**。変更するなら
  **オンラインサロン担当へ直接連絡**して足並みを揃えること（※ 2026-08-28 以降、受付=COO 経由ではない。下記「体制」参照）。※値はここに書かない（所在は本番ページのゲート内）。
- 🔴 **約束と境界を取り違えない**（2026-08-28）。`.vercelignore`・`AGENTS.md`・各種設定は「**そうしてくれ**」という
  **約束**であって、**境界（そもそも到達できない）ではない**。設定ミス・移行・別経路では守られない。
  ➡️ **BCC の安全は「機密をリポに置かない」で成立させる。`.vercelignore` はその上の二重化であって、

  ⚠️ **訂正（2026-08-29）**: 以前ここに「`AGENTS.md` を作っていない＝無いリポでは委譲しないという柵が効いている」と
